A Dialog presents content in a modal overlay that interrupts the current page, requiring user action before returning to the main flow.

<DialogDemo client:load />

## Anatomy

A dialog consists of up to 11 parts:

| Part | Required | Description |
|------|----------|-------------|
| DialogRoot | Yes | Controls open state and modality |
| DialogPortal | Yes | Teleports overlay and content to `body` |
| DialogOverlay | Yes | Semi-transparent backdrop behind the dialog |
| DialogContent | Yes | The dialog panel |
| DialogHeader | Yes | Header section containing title and optional description |
| DialogBody | No | Scrollable content area between header and footer |
| DialogFooter | No | Action buttons container at the bottom |
| DialogTitle | Yes | Accessible heading for the dialog |
| DialogDescription | No | Optional description — placed in either `MizuDialogHeader` or `MizuDialogBody` |
| DialogClose | No | Close button (X icon). Placed directly inside `MizuDialogContent` for absolute positioning |
| DialogTrigger | Yes | Button or element that opens the dialog |

## Composition

`MizuDialogClose` can be placed directly inside `MizuDialogContent` (for absolute top-right positioning) or inside `MizuDialogHeader`. `MizuDialogDescription` can live in either `MizuDialogHeader` or `MizuDialogBody`.

```
MizuDialogRoot
  MizuDialogTrigger
  MizuDialogPortal
    MizuDialogOverlay
    MizuDialogContent
      MizuDialogClose (optional — inside content for top-right placement)
      MizuDialogHeader
        MizuDialogTitle
        MizuDialogDescription (optional — or in MizuDialogBody)
      MizuDialogBody (optional)
        ... (scrollable content, description)
      MizuDialogFooter (optional)
        ... (action buttons)
```

### MizuDialogRoot

Wrapper around `DialogRoot`. Controls open state and modality.

### MizuDialogPortal

Teleports overlay and content to `document.body` by default. Accepts a custom `to` target.

### MizuDialogOverlay

Semi-transparent backdrop (`rgba(0, 0, 0, 0.5)`) with fade-in/out animation. Only renders when `modal` is `true` on the root.

### MizuDialogContent

The dialog panel. Centered on screen with `max-width: 450px`, white background, rounded corners, and a scale-in animation. Uses `display: flex; flex-direction: column` to enable the header-body-footer layout.

### MizuDialogHeader

Header section containing the title and optional description. Has a bottom border separator and reduced gap for a compact layout. The close button (`MizuDialogClose`) is typically placed directly inside `MizuDialogContent` for top-right positioning.

### MizuDialogBody

Scrollable content area between header and footer. Has `overflow-y: auto` and a capped height to prevent the dialog from growing too tall. Only scrolls when content overflows.

### MizuDialogFooter

Action buttons container at the bottom. Has a top border separator and a right-aligned flex layout with consistent button gap.

### MizuDialogTitle

Renders as an `<h2>` by default. Linked to the dialog via `aria-labelledby`.

### MizuDialogDescription

Renders as a `<p>` by default. Linked to the dialog via `aria-describedby`.

### MizuDialogClose

Renders as a `<button>` with an X icon by default. Pass `as-child` to use a custom element. Positioned absolutely at the top-right of the content panel. Place directly inside `MizuDialogContent` (before the header) for proper positioning.

### MizuDialogTrigger

Renders as a `<button>` by default. Sets `aria-haspopup="dialog"` and `aria-expanded` for accessibility.

## Accessibility

### Requirements

| Criterion | Implementation |
|-----------|---------------|
| Focus trap | Reka UI DialogContentModal traps focus within the dialog while open |
| Body scroll lock | Reka UI disables background scrolling when dialog is open |
| Escape key | Reka UI closes dialog on Escape key press |
| Outside click | Reka UI closes dialog on click outside content (modal mode) |
| ARIA role | Dialog content has `role="dialog"` and `aria-modal="true"` |
| ARIA labelling | `aria-labelledby` links to DialogTitle; `aria-describedby` links to DialogDescription |
| Focus return | Focus returns to the trigger element when dialog closes |

### ARIA Attributes

```html
<div role="dialog" aria-modal="true" aria-labelledby="dialog-title" aria-describedby="dialog-desc">
  <h2 id="dialog-title">Confirm Deletion</h2>
  <p id="dialog-desc">Are you sure? This cannot be undone.</p>
  <button aria-label="Close">X</button>
</div>
```

### Basic

```vue
<script setup lang="ts">
import { ref } from "vue";
import {
  MizuDialogRoot,
  MizuDialogPortal,
  MizuDialogOverlay,
  MizuDialogContent,
  MizuDialogHeader,
  MizuDialogBody,
  MizuDialogFooter,
  MizuDialogTitle,
  MizuDialogDescription,
  MizuDialogTrigger,
  MizuButton,
} from "@mizu/vue";

const open = ref(false);
</script>

<template>
  <MizuDialogRoot v-model:open="open">
    <MizuDialogTrigger as-child>
      <MizuButton variant="accent" size="md" class="w-max">Open Dialog</MizuButton>
    </MizuDialogTrigger>
    <MizuDialogPortal>
      <MizuDialogOverlay />
      <MizuDialogContent>
        <MizuDialogHeader>
          <MizuDialogTitle>Confirm Deletion</MizuDialogTitle>
        </MizuDialogHeader>
        <MizuDialogBody>
          <MizuDialogDescription>
            Are you sure you want to delete this invoice?
          </MizuDialogDescription>
          <p>This action cannot be undone. All associated data will be permanently removed.</p>
        </MizuDialogBody>
        <MizuDialogFooter>
          <MizuButton variant="ghost" size="md" class="w-max" @click="open = false">Cancel</MizuButton>
          <MizuButton variant="accent" size="md" class="w-max" @click="open = false">Delete</MizuButton>
        </MizuDialogFooter>
      </MizuDialogContent>
    </MizuDialogPortal>
  </MizuDialogRoot>
</template>
```

## Implementation Notes

1. **DialogPortal teleports to body** — `MizuDialogPortal` defaults `to` to `"body"` to avoid Starlight CSS bleed and stacking context issues. Set `to` to a custom selector if you need containment.
2. **DialogOverlay only renders in modal mode** — When `modal` is `false` on `MizuDialogRoot`, `DialogOverlay` is not rendered (Reka UI behavior).
3. **CSS `translate` for centering** — Content uses the `translate` property (not `transform`) for centering, avoiding conflicts with Reka UI's Popper inline styles. The scale animation uses `transform: scale()` which is a separate property and does not conflict.
4. **Close button absolute positioning** — `MizuDialogClose` is positioned absolutely at the top-right of the content panel. Ensure `MizuDialogContent` serves as the positioning anchor.
5. **Focus management** — Reka UI handles focus trap, auto-focus on open, and focus return on close. The `openAutoFocus` and `closeAutoFocus` events can be used to customize this behavior.
6. **Flex column layout** — `MizuDialogContent` uses `display: flex; flex-direction: column` so `MizuDialogBody` can fill available space while header and footer stay pinned.
7. **Body scrolling** — `MizuDialogBody` has `overflow-y: auto` and a capped height. When content exceeds the available space, only the body scrolls while the header and footer remain visible.
8. **`asChild` pattern** — All Reka-wrapping sub-components support `asChild` for composition. Use `MizuDialogTrigger as-child` with `MizuButton` to style the trigger as a button. Use `MizuDialogClose as-child` with `MizuButton` for a custom close button.
