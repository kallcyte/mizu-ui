TagsInput is a text field that converts typed entries into a list of removable tag chips. It is used wherever users need to assign multiple discrete values to an entity — labels, skills, recipients, categories.

<TagsInputDemo client:load />

## Anatomy

A TagsInput consists of up to 5 parts:

| Part | Required | Description |
|------|----------|-------------|
| Wrapper | Yes | Layout shell with vertical label → control → helper text stack (same as `MizuInput`) |
| Container | Yes | The chip-and-input "well" reusing `MizuInput`'s `.bp-input` styling |
| `MizuTag` Chip | No | A closable `MizuTag` pill for each committed value |
| Native Input | Yes | The trailing transparent text field where new values are typed |
| Helper Text | No | Optional hint shown below the control (or an error message) |

## Variants

## Touch Target

The chip-level remove button is 12×12px (visual) but the surrounding chip area keeps the combined interactive area accessible to pointer activation. The container itself never collapses below 28/36/40px min-height, providing the WCAG 2.5.8 minimum target on its own.

## Accessibility

### Requirements

| Criterion | Implementation |
|-----------|----------------|
| Color Contrast | 4.5:1 for chip label text via `brand-primary` / `feedback-*-base` |
| Keyboard | `Enter`, `,`, `;`, `Tab` commit a tag; `Backspace` removes the last tag when input is empty |
| Screen Reader | Container announces as `role="group"`; helper text linked via `aria-describedby`; remove button uses `aria-label="Remove {tag}"` |
| Disabled | `aria-disabled="true"` on container; native `disabled` on input |
| Required | `aria-required="true"` on container; visual asterisk in label |
| Invalid | `aria-invalid="true"` on container when `error` is set |

### Events

| Event | Payload | Description |
|-------|---------|-------------|
| `update:modelValue` | `string[]` | Emitted on every commit and remove (use with `v-model`) |
| `add` | `string` | Emitted when a tag is committed |
| `remove` | `string` | Emitted when a tag is removed (via button or Backspace) |
| `focus` | `FocusEvent` | Emitted when the trailing input receives focus |
| `blur` | `FocusEvent` | Emitted when the trailing input loses focus |
| `invalid-tag` | `[value: string, reason: 'duplicate' \| 'max' \| 'validation']` | Emitted when a tag is rejected |

### Slots

This component does not expose named slots — chips are rendered from `modelValue`.

### Example Usage

```vue
<script setup lang="ts">
import { ref } from "vue";
import { MizuTagsInput } from "@mizu/vue";

const skills = ref<string[]>(["Vue", "TypeScript"]);

function isKebab(value: string) {
  return /^[a-z0-9-]+$/.test(value);
}
</script>

<template>
  <MizuTagsInput
    v-model="skills"
    label="Skills"
    helper-text="Press Enter or comma to add a tag"
    placeholder="Add a skill..."
    tag-variant="accent"
    :max-tags="8"
    :validate="isKebab"
  />
</template>
```

## Implementation Notes

1. **Composition** — the container reuses `MizuInput`'s `.bp-input` class, so focus, error, and disabled states are visually identical to the standalone input. Chips are rendered with the existing `MizuTag` component, so the color palette, close button, and accessibility are inherited rather than duplicated.
2. **Tag variant option** — the `tagVariant` prop maps directly to `MizuTag`'s `variant` prop, allowing consumers to choose the chip color scheme independently from the input size.
3. **Controlled / uncontrolled** — when `modelValue` is `undefined`, TagsInput holds its own internal `ref` and only emits on change; passing `v-model` makes it fully controlled.
4. **Multi-separator support** — the `separator` prop is a list of keys / characters; any of them commit a tag, and pasted strings are split on every configured separator at paste time.
5. **Whitespace trimming** — committed values are `.trim()`-ed before validation, so leading/trailing whitespace never produces blank or duplicate-looking tags.
6. **Duplicate rejection** — controlled by `allowDuplicates`; rejected duplicates fire `invalid-tag` with `reason: 'duplicate'` and flash the most recently added chip.
7. **Custom validation** — `validate(value)` returning `false` or `""` rejects the tag; returning `true` accepts it. No tag is silently dropped.
8. **Backspace deletion** — when the input is empty and focus is inside the container, `Backspace` removes the last tag and refocuses the input automatically.
9. **Blur commits** — leaving the field while text is still in the input commits the pending value (trimmed).
10. **Inline animations** — chips animate in via a 150ms `scale(0.85) → scale(1)` pop; rejected commits trigger a 200ms `translateX` shake on the most recent chip.
11. **Tailwind `@apply`** — uses `@apply` + `@reference "../index.css"` for Tailwind v4 compatibility; the `MizuTag` component already handles its own token binding.
12. **Class inheritance** — accepts `class` from `useAttrs()` to allow consumers to override container-level styling without losing the `bp-input` hooks.
