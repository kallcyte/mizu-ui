A badge is a small, compact indicator used to display counts, statuses, or short labels. It can render as a dot for presence indicators, a number for notification counts, or inline text for status labels. Badges are typically positioned relative to another element (such as an avatar or button) using the `position` prop.

## Examples

<BadgeDemo client:only="vue" />

```vue
<!-- Count badge -->
<MizuBadge :count="5" />

<!-- Dot indicator -->
<MizuBadge dot variant="success" />

<!-- Positioned on avatar (auto-wraps in relative container) -->
<MizuBadge :count="3" variant="error" position="top-right">
  <MizuAvatar name="Jane Doe" size="lg" />
</MizuBadge>

<!-- Simple value display (replaces Chip use case) -->
<MizuBadge value="New" variant="accent" />

<!-- Custom max overflow -->
<MizuBadge :count="1500" :max="999" />  <!-- 999+ -->

<!-- Show zero -->
<MizuBadge :count="0" show-zero />

<!-- Small dot for presence -->
<MizuBadge dot variant="success" size="sm" />
```

## API

### Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `'primary' \| 'accent' \| 'success' \| 'warning' \| 'error' \| 'info'` | `'error'` | Visual variant |
| `size` | `'sm' \| 'md'` | `'md'` | Badge size |
| `dot` | `boolean` | `false` | Render as a dot indicator (ignores content) |
| `value` | `string \| number` | `undefined` | Simple display text (takes priority over `count`). Replaces the need for `MizuChip`. |
| `count` | `number` | `undefined` | Numeric count to display |
| `max` | `number` | `99` | Maximum count before overflow (`{max}+`) |
| `showZero` | `boolean` | `false` | Show badge when count is 0 |
| `position` | `'inline' \| 'top-right' \| 'top-left' \| 'bottom-right' \| 'bottom-left'` | `'inline'` | Absolute positioning relative to parent |

### Slots

| Slot | Description |
|------|-------------|
| `default` | Custom content (text label when `position="inline"`, parent element when position is a corner) |

## Theme

### CSS Custom Properties

Customize the badge appearance with these CSS custom properties:

| Token | Default | Description |
|-------|---------|-------------|
| `--color-brand-primary` | #001C44 | Primary variant background |
| `--color-brand-ycp` | #007FFF | Accent variant background |
| `--color-feedback-success-base` | #15803D | Success variant background |
| `--color-feedback-warning-base` | #D97706 | Warning variant background |
| `--color-feedback-error-base` | #DC2626 | Error variant background |
| `--color-feedback-info-base` | #0284C7 | Info variant background |
| `--color-foreground-inverse` | #FFFFFF | Content text color (all variants) |
| `--font-weight-medium` | 500 | Content font weight |

#### Variant Color Map

All variants use a solid fill with inverse text for high contrast against their background:

| Variant | Background | Text Color | Use Case |
|---------|------------|------------|----------|
| **Primary** | `brand-primary` | `foreground-inverse` | Brand emphasis, primary notifications |
| **Accent** | `brand-ycp` | `foreground-inverse` | Interactive highlights, new items |
| **Success** | `feedback-success-base` | `foreground-inverse` | Online status, completed items |
| **Warning** | `feedback-warning-base` | `foreground-inverse` | Pending items, warnings |
| **Error** | `feedback-error-base` | `foreground-inverse` | Error counts, critical alerts |
| **Info** | `feedback-info-base` | `foreground-inverse` | Informational counts, neutral status |

Badges do not have interactive states (hover, focus, pressed) as they are non-interactive indicators.

#### Count Overflow

When the `count` prop exceeds the `max` value (default: 99), the badge displays `{max}+`. When `count` is `0` and `showZero` is `false` (default), the badge is hidden.

| `count` | `max` | `showZero` | Display |
|---------|-------|------------|---------|
| 0 | 99 | false | Hidden |
| 0 | 99 | true | `0` |
| 5 | 99 | — | `5` |
| 99 | 99 | — | `99` |
| 100 | 99 | — | `99+` |
| 1500 | 999 | — | `999+` |

#### Positioned Badge Layout

When `position` is set to a corner and a slot is provided, the badge wraps the slot in a `.mizu-badge-wrapper` (`position: relative`) and overlays itself automatically. When no slot is provided, the parent must have `position: relative`.

```
┌─────────────────────────┐
│                    ┌──┐ │
│                    │5 │ │  ← top-right
│                    └──┘ │
│                         │
└─────────────────────────┘
```

| Position | Top | Right | Bottom | Left | Transform |
|----------|-----|-------|--------|------|-----------|
| `top-right` | 0 | 0 | — | — | `translate(50%, -50%)` |
| `top-left` | 0 | — | — | 0 | `translate(-50%, -50%)` |
| `bottom-right` | — | 0 | 0 | — | `translate(50%, 50%)` |
| `bottom-left` | — | — | 0 | 0 | `translate(-50%, 50%)` |

### Accessibility

| Criterion | Implementation |
|-----------|----------------|
| Color Contrast | 4.5:1 for count/text content against solid background |
| Screen Reader | `role="status"` on the badge element |
| Non-interactive | Badge is a `<span>`, not focusable; decorative when positioned |
| Semantic | Count content is announced by screen readers via `role="status"` |

```html
<span class="mizu-badge mizu-badge--error mizu-badge--md" role="status">5</span>

<!-- Dot mode -->
<span class="mizu-badge mizu-badge--success mizu-badge--sm mizu-badge--dot" role="status"></span>
```

## Anatomy

A badge consists of up to 2 parts:

| Part | Required | Description |
|------|----------|-------------|
| Container | Yes | The badge's background and shape |
| Content | No | Count, text, or dot indicator |

## Implementation Notes

1. **Native `<span>` element** — No Reka UI primitive needed; the badge is a lightweight inline indicator
2. **Solid fill** — Unlike Tag (which uses subtle backgrounds), Badge uses solid backgrounds with inverse text for maximum contrast at small sizes
3. **Positioning** — The `position` prop applies `position: absolute` with `transform` for centering. When a slot is provided, the badge auto-wraps in `.mizu-badge-wrapper` (relative). Without a slot, the parent must have `position: relative`.
4. **Count formatting** — When `count` exceeds `max`, displays `{max}+`; when `count` is 0 and `showZero` is false, the badge is hidden entirely
5. **Dot mode** — Renders as a small circle (8px sm, 10px md) with no content; useful for presence/status indicators
6. **Slot fallback** — When `position="inline"` and neither `dot`, `value`, nor `count` is provided, the default slot is rendered as text content. When position is a corner, the slot becomes the element the badge overlays.
7. **Value mode** — The `value` prop provides a simple text display (like Chip) without count formatting. When set, it takes priority over `count`.
8. **Tabular nums** — Uses `font-variant-numeric: tabular-nums` for consistent digit width in counts
9. **Tailwind `@apply`** — Component styles use `@apply` with `@reference` for Tailwind v4 compatibility
10. **CSS Custom Properties** — Colors are resolved at runtime via CSS custom properties
11. **Self-contained CSS** — Tailwind utilities are bundled into `dist/index.css` via `@tailwindcss/vite`; consumers do not need Tailwind installed
12. **Class inheritance** — Accept `class` prop for overrides via `useAttrs()`
13. **TypeScript** — Full type safety with `<script setup lang="ts">`
14. **Tree-shakeable** — Export as ESM + CJS via Vite library mode
