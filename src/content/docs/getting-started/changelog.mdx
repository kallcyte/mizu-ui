## Versioning

This project follows **semantic versioning** (SemVer) during pre-1.0 development (`0.x.y`):

| Bump | When |
|------|------|
| **Patch** (`0.2.x`) | Bug fixes, documentation updates, minor refactors, dependency bumps |
| **Minor** (`0.x.0`) | New features, new components, breaking token/API changes |
| **Major** (`1.0.0`) | Stable production release |

Changes that require a minor bump: adding a new component, renaming tokens, changing component APIs, adding new packages (e.g. React).
Changes that keep the patch version: renames, copy edits, styling tweaks, build config changes, favicon updates.

## 0.6.0 (2026-06-05)

### Added

- **`MizuAvatar`** — user/entity avatar with `src` (image), `name` (initials fallback), `alt` (decorative), 4 sizes (sm/md/lg/xl: 24/32/40/56px), 2 shapes (`circle` / `square` with size-scaled radius), 4 color variants (`muted` / `primary` / `accent` / `neutral`), and an `icon` slot for custom fallback content. Built-in source priority: `src` (image) → `name` (initials) → `icon` slot → default person silhouette SVG. Uses native `<div role="img">` with possessive `aria-label` (e.g. "Mariko Tanaka's avatar").
- **Component card for Avatar** added to the homepage Components section.
- **MizuAvatar demo** with 11 sections: Basic, With Image, Sizes, Sizes With Image, Shapes, Color Variants, Anonymous, Custom Icon Slot, Team List, Comment Thread, Profile Header.

### Fixed

- **Dark mode backgrounds in AvatarDemo** — `.team-list`, `.team-row`, `.comment`, and `.profile` now switch to `var(--sl-color-black)` background and `var(--sl-color-gray-5)` border when `<html data-theme="dark">` is active. Selector pattern updated to use `:global(html[data-theme="dark"] .class)` so the class selector survives Vue scoped CSS compilation.
- **Muted text contrast in dark mode** — secondary text (`.team-meta`, `.comment-time`, `.profile-role`) now uses `--sl-color-text-light` (resolves to `--color-foreground-secondary`: #94A3B8 in dark mode) instead of `--sl-color-gray-5` (#3B3F52, too dark for text on black).

### Documentation

- New MDX page: `avatar.mdx` — full skill-spec structure (anatomy, variants, color/size specs, typography, shape, source priority, spacing, accessibility, token mapping, Vue API, implementation notes).
- Sidebar Components list updated to include Avatar (alphabetical order).

## 0.5.0 (2026-06-05)

### Added

- **`MizuInput`** — text input with `label`, `helperText`, `error` state, `prefix` / `suffix` slots, 3 sizes (sm/md/lg), disabled, required, and `type` support (text, email, password, number, tel, url, search). Uses native `<input>` for full form integration; aria-invalid and aria-describedby wired to error/helper text.
- **`MizuAlert`** — feedback messaging with 4 variants (`success`, `error`, `warning`, `info`), optional `title`, default and `compact` density, and `dismissible` mode (rendered with a `lucide-vue` `X` icon). No buttons or actions — messaging only.
- **`MizuCheckbox`** — tri-state checkbox with checked / unchecked / `indeterminate`, `disabled`, `required`, optional inline `label`, custom `trueValue` / `falseValue` for non-boolean bindings, and unique id via `useId()`. Built on Reka UI `CheckboxRoot` + `CheckboxIndicator` for accessibility.
- **`reka-ui@^2.9.0`** added as a peer-style dependency of `@mizu/vue` for primitive accessibility.
- Component cards for **Alert**, **Checkbox**, and **Input** added to the homepage Components section.

### Fixed

- **`MizuButton` sm size** corrected to match the design system spec (22px → 28px height). Other sizes were already correct.
- **Starlight list markers** in `.sl-markdown-content` ordered/unordered lists were inheriting `none` from Starlight defaults; added explicit `list-style` rules in `starlight.css`.

### Documentation

- New MDX pages: `alert.mdx`, `checkbox.mdx`, `input.mdx` — each following the skill-spec skeleton (anatomy, variants, color/state map, token mapping, Vue component API, implementation notes).
- `button.mdx` size-specification table updated to reflect the corrected sm height.
- `PLAN.md` §"Form Validation (Future)" added — documents that validation lives in the consumer layer and lists three candidate approaches (hand-rolled composable, VeeValidate + Zod, thin `useMizuField` wrapper).

## 0.4.1 (2026-06-05)

### Added

- **Single source of truth for tokens** — `@mizu/tokens` (built from `tokens.json`) now generates `light.css`, `dark.css`, `tailwind.css` (Tailwind v4 `@theme`), and `starlight.css` (Starlight `--sl-*` mappings). Replaces the duplicated hardcoded values in `packages/vue/src/index.css`, `src/styles/tokens.css`, and `src/styles/starlight.css`.
- **Dark mode coverage** — added `color/dark/brand/primary-focus`, `secondary/hover/focus/subtle`, `neutral`, and full `feedback/{success,error,warning,info}/{base,hover,focus,subtle}` trees. Also added `shadow/dark/{ring,whisper}` so cards and hover states render correctly in dark mode.
- **Starlight theme variables** — generated `starlight.css` emits `--sl-color-*` mappings, the required 9-step gray ramp, type scale, and radii. `--sl-color-white` / `--sl-color-black` hardcoded as constants to match Starlight's "always-light/always-dark" intent.
- **Tag pill styles** — `.tag`, `.tag-accent`, `.tag-warning` defined in `docs.css` using Mizu tokens.
- **"Coming soon" pills** on the Login and Dashboard sample cards in the See It section.

### Changed

- **Breaking: token naming** — all color/typography/spacing tokens now use canonical `--color-*`, `--font-size-*`, `--line-height-*`, `--letter-spacing-*` etc. (the legacy `--bp-color-*` prefix on token references is removed across all Vue SFCs).
- **`tokens.css` aggregate removed** — consumers now import the four specialized subpaths (`@mizu/tokens/light.css`, `@mizu/tokens/dark.css`, `@mizu/tokens/tailwind.css`, `@mizu/tokens/starlight.css`) instead of a single bundled aggregate.
- **Homepage sections** — removed `Manifesto` and `AntiPatterns` sections from the homepage.
- **Starlight dropdown + select theming** — search button, theme select, and mobile-TOC dropdown all use `--sl-color-bg-nav` for background and explicit `var(--sl-color-gray-2)` for dropdown text. Theme-select `<option>` elements use hardcoded `#ffffff` / `#1B1B1D` (light) and `#1B1B1D` / `#F1F5F9` (dark) to avoid white-on-white.
- **Visible Starlight elements** — added explicit `color` overrides for page title (`h1.astro-n5dwoyeh`), markdown headings, table headers, summary, aside, link hovers, large sidebar labels, link buttons, kudos, and step number circles. Starlight's defaults use `var(--sl-color-white)` for text, which becomes invisible on Mizu's white page background in light mode.
- **PLAN.md** — §"Token System" rewritten with the build pipeline, consumer table, naming convention, and Tailwind/Starlight mapping tables. §"shadcn adapter" updated (`--destructive` → `feedback-error-base`). Key Decisions expanded to document the single-source-of-truth approach and breaking token rename.
- **`@mizu/tokens` 0.4.1**, **`@mizu/vue` 0.4.1** — versions aligned so the GitHub release workflow produces a single `v0.4.1` tag.

### Fixed

- Dark-mode shadows (`--shadow-ring`, `--shadow-whisper`) now resolve to the dark values (`#1E2030` border, `rgba(0,0,0,0.24)` elevation) instead of leaking the light values. The build script's `isDarkPath()` helper generalizes dark-override emission to both `color/dark/*` and `shadow/dark/*` paths.
- White-on-white text in the Starlight docs sidebar and page title (root cause: theme-aware `--sl-color-white` mapping; fix: hardcoded constants in `starlight.css`).
- Theme-select dropdown options showing white text on white background in light mode (root cause: same theme-aware `--sl-color-white` mapping; fix: hardcoded hex values per theme).
